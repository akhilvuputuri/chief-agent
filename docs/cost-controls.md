# Token efficiency and usage visibility

There is **no new dollar cap**. The user explicitly declined the proposed $1 allocation. `/continue` retains its existing time/model/tool behavior; no monetary allocation is added. Existing model and provider-routing settings are unchanged.

## Measured problem

The latest 22-role run used 16 Sol calls, 326,051 input tokens, 7,193 output tokens (394 reasoning tokens), zero cache hits and $0.8870335 reported main-model cost. Input accounted for $0.8151035. It attempted 57 searches using only 37 distinct strings, then exhausted 100 tools before a final answer. Search inference/plugin usage was discarded by the old adapter, so that total excluded part of the bill.

## Changes

- Keep instructions and explicit memories in a stable opening message. Put changing time, checkpoints, inventories and usage summaries in a separate message after selected history. Pass an opaque runtime run ID as OpenRouter `session_id` for provider stickiness within a turn. Continuations get new run IDs; cross-turn cache reuse is not guaranteed.
- Reduce the total context character allowance from 100,000 to 48,000, including instructions, schemas, memories and current state. Preserve complete tool/result groups, the current request and compact inventories. Full observations remain retrievable. Medium reasoning and the 8,000-output-token capacity remain unchanged: input dominated the observed bill. (Since the enabling change of [journal 161](journey/161-enabling-direct-anthropic.md), owner-approved on 11 November 2026, Chief's agent loop, the nightly learner's two passes and the judge each ask for 32,000 output tokens; a caller that sends no allowance gets 8,000.)
- Reuse normalized identical successful searches within the same owner and attached task/run for one hour. Cached observations do not extend original expiry. New unrelated tasks search fresh; semantic variants are not deduplicated. Source data remains untrusted.
- Record main-model and search-helper usage, including reported dollar cost, token counts and cache details. Begin a persisted accounting record before dispatch, then settle with reported usage. Missing/failed-request cost remains unknown with a separate estimate. It is never presented as an actual charge or as zero-cost success.
- Tell the agent to reuse research, read promising original pages before searching again, correct failed source quotes and prioritize useful synthesis over marginal repeated discovery.

## Accounting schema and estimates

Additive migration 008 creates `provider_charges`, linked to owner-scoped runtime runs. `actual_usd` is nullable. `estimated_usd` is an accounting hint for requests whose cost is unavailable, not a reservation against a budget. `usage` retains provider metadata. The current task's reported cost, unknown-cost count and estimate total are supplied to the model separately. This never blocks a request based on dollars.

Main-model estimates use input UTF-8 bytes plus an overhead allowance, configured prices with a 1.25 cache-write multiplier, and maximum output capacity. They deliberately overestimate typical use. Unknown search requests use a $0.10 policy estimate; optional Tavily calls use $0.05 because dollar usage is unavailable. These are not invoice amounts or guaranteed billing bounds. Successful OpenRouter requests use the returned `usage.cost`; no guessed plugin fee is added separately.

Speech runs outside the task loop and is not included here. Neither are infrastructure, other applications sharing the key or historical requests before migration. This ledger is not a complete provider bill. Existing base-price routing filters do not cap cache-write premiums or total task spending.

### Direct Anthropic route

Not yet enabled in production; the owner-approved enabling change is prepared ([model providers](model-providers.md), [journal 161](journey/161-enabling-direct-anthropic.md)). A call served directly by Anthropic records its charge under `anthropic-main`; OpenRouter calls, including a fallback after a direct failure, keep `openrouter-main`. Its estimate is formed the same way, from the policy's list input price with the 1.25 multiplier and the full output allowance. Anthropic returns no dollar cost, so the settled cost is computed from the token counts and the reviewed prices in `config/model-policy.json`: uncached input, cache reads (`cacheRead`, $0.20/M for Opus 5.5), 5-minute cache writes (`cacheWrite`, $5/M) and output. It is a priced estimate of the invoice, not a provider-reported amount, and is wrong if those prices drift from Anthropic's. A direct attempt that fails and falls back leaves its estimate unsettled, beside the settled OpenRouter charge. The OpenRouter price ceilings do not apply on this route; instead a mapped model goes direct only while its listed prices fit them. Server-side refusal fallbacks are deliberately not requested, because they can serve a call on a different model (Opus 5 or Opus 4.8, $5/$25) above those ceilings, which this computed cost would also misprice; a refusal simply fails. A rejected request (HTTP 400) before any output falls back to OpenRouter, priced there as usual; a call retried once on the direct route without a rejected thinking replay settles its one charge with the successful attempt's tokens (the failed 400 attempt produces no tokens to price). Requests send no top-level automatic cache mark, so no cache-write premium is paid on the per-call state message. A call that fails after a complete response was received (a refusal, an incomplete or empty response) is still billed: its charge settles with the response's tokens, its error diagnostics carry the normalized usage, and its `model.failed` log line and span carry its tokens and cost; a coding job also records it as a `model_usage` event marked `incomplete`.

Measured live on 11 November 2026 with a temporary key (local runs, not production; [details](model-providers.md#live-verification-11-november-2026)): 95% of input read from cache on a stable 10.5k-token prefix; 76% of prompt tokens read from cache across 68 calls of Chief's real loop; Pi plan, code and review jobs at about $0.25 each. Replayed thinking used to be dropped on every later call of a turn, because Chief rebuilds its trailing state message each call; the adapter now restores each block's original state message, and on Chief's real `tools` scenario that took drops from 16 of 16 to 0 while cache reads went from 84.7% to 85.8% of prompt tokens and direct-call cost from $0.45 to $0.38. Output allowances, decided by the owner on 11 November 2026 ([journal 161](journey/161-enabling-direct-anthropic.md)): Chief's agent loop 32,000 tokens (the 8,000-token default, which includes thinking, failed 3 of 6 deliberately hard prompts as empty responses), the coding reviewer 64,000, the coder and planner unchanged at 128,000 (one trivial call under it spent 91k output tokens, $1.82) and on Opus 5.5 too. Later that day the owner raised the nightly learner's review pass (from 8,000), its procedure pass (from 16,000) and the judge (from 8,000) to 32,000 as well; their five-minute call limit is unchanged, so a call slower than about 107 tokens a second cannot use the whole allowance ([learning](learning.md#host-checks)). Each call's pre-call estimate counts its whole allowance at the adapter's output price ($20 a million, the OpenRouter ceiling or Opus 5.5's list price), so a Chief, review-pass or judge call's estimate rises by $0.48 and a procedure call's by $0.32; the estimate is an accounting hint, never a cap. The judge (`openai/gpt-6.1-sol`) is billed at $10 a million output tokens, so its whole allowance costs at most $0.32. A night in which all 70 review, 20 procedure and 14 judge calls used every token would cost about $62 in output (computed upper bound, unreachable within the call limit at 100 tokens a second; the last measured review run took 39 seconds for 40 items). At $20 per million output tokens, a call that uses its whole allowance costs at most $0.64 (Chief), $1.28 (reviewer) or $2.56 (coder), plus input (computed, not measured).

> **Update, 11 November 2026 ([journal 164](journey/164-claude-models-everywhere.md)):** the judge is Opus 5.5 ($20 a million output tokens, so its whole 32,000 allowance costs at most $0.64) and the `fast` tier is Haiku 5.5 ($0.10 / $0.50). Anthropic charges Haiku $0.50 / $2.50 above 100,000 prompt tokens, which the adapter's recorded cost does not reflect. With the judge at $20 instead of $10, the computed upper bound for a night in which every call uses its whole allowance rises from about $62 to about $67 in output.

## Context allowance follow-up — 13 September 2026

The 48,000-character allowance is unchanged, but it now bounds prior history rather than acting as a turn precondition. Tool schemas and runtime state have grown to roughly 30,000 characters before any message, so a user turn carrying a document excerpt can push the fixed part close to or over the allowance. On 12 September (18:46 UTC) such a turn failed 36 ms after its first model allocation with no provider diagnostics and the user saw a generic execution error. The guard throwing is the most plausible cause given the timing signature and local measurement of the same file; the live state size was inferred, not captured, because the failure predates the traces added here.

Behavior now: the current user message and this turn's newest tool group (the assistant call and its results) form a floor that is always sent, so the model never loses the results it just requested. Prior history and older in-turn tool groups share the unchanged 48,000-character allowance newest-first, exactly as before, so the per-request ceiling for ordinary long turns is unchanged. Only when the fixed part plus that floor already exceed the allowance does a request exceed it; that case records one `context.over_budget` event per turn (info level since journal 101, with `kind` `fixed` or `protected`) with the measured fixed and floor sizes; older history then still gets a capped 6,000-character `historyFloor`, and the trailing state line tells the model that only the current message and its newest results are included. When reading event frequency, note that the event can also fire mid-turn when the newest tool group itself is large (for example an 8,000-character projected observation on top of a 36,000-character fixed part); `reservedSize` distinguishes that from an oversized fixed part, which is the compaction trigger. A fixed part plus floor beyond a 120,000-character hard limit is refused, and that refusal records its sizes in `model.failed` instead of failing silently. Non-provider failures in the model step also record a bounded error identity. The inline PDF excerpt stays at 6,000 characters; reducing it, or compacting tool descriptions, are the next levers if `context.over_budget` events appear regularly.

# Coding progress, context and model recovery

This contract applies to Python 0.1.5 jobs with the reviewed `harnessVersion: 2` selector. The host foundation alone does not activate it. Publish from independently reviewed main, verify the anonymous immutable image and installed source, then pin that digest and selector together. No database/Compose/credential change is required. Older jobs keep their pinned settings and image; resume does not upgrade them.

## Durable observations

`checkpoint.runtimeMemory` is bounded private JSON, fenced by the same objective/context/base/approved-plan scope hash as the squad. Leader, coder and reviewer each have their own notebook, evidence receipts and counters. Notes contain the subtask, findings with evidence references, next action and questions/rejected hypotheses. The automatic ledger stores hashes, safe file paths and delivered ranges rather than raw file/log/command content. It retains the 80 most recent distinct receipts per member and a 16-observation loop window. Notebook text is bounded to 10,000 UTF-16 units per member.

Working state is not approved scope, a passing check or review authority. It is excluded from the code artifact hash and never published into the repository. The owner-approved plan remains immutable; actual sandbox checks and independent review of the exact candidate remain required. A new reviewer receives a fresh context and notebook for each candidate. Explicit resume preserves same-scope notes/evidence and resets notebook per-attempt counters/intervention levels; existing shared allocation/cancellation rules remain authoritative. Scope changes discard incompatible working state.

The runtime acknowledges lightweight working-state checkpoints before provider requests and after read batches, as well as after notes updates. These retain the acknowledged artifact without running Git snapshot commands for every read. Writes/commands keep their existing immediate artifact checkpoint and uncertain-outcome fences. A failed checkpoint stops rather than pretending its new state was committed.

## Navigation and context

`glob` inventories safe Git-visible files, respecting ignores and existing credential/workflow/symlink restrictions. `grep` executes ripgrep through a bounded argv call, with literal/regex search, file filtering, line numbers and pagination. Search is limited to 1,000 selected paths, 100 matching lines per file, bounded output and 15 seconds; an exceeded bound requests narrower inspection rather than silently claiming complete coverage. `file_read` accepts legacy Unicode character offsets or one-based line ranges, returns a byte fingerprint and actual delivered character range, and exposes a continuation cursor. File access remains on the sandbox; no production shell access is added.

Before context exceeds 100 KB or 80 messages, the same member makes a tools-restricted summary request that can only update its notebook. This consumes the existing shared model/tool allocation. The replacement notebook must be acknowledged before old groups are removed. Original instructions/brief and the newest complete assistant/tool group remain intact, including opaque reasoning. The normal trimmed target is 80 KB/60 messages. If a protected group or summary cannot fit, or summary validation/checkpoint fails, the worker pauses with the last acknowledged state. Wire-byte limits remain separate from model token windows; summary quality is fallible and needs evaluation.

Runtime-generated allocation/notebook hints are replaced between requests rather than accumulating. The notebook and bounded evidence index are reintroduced after compaction and resume; `notes_read` pages the retained notebook/ledger. The existing complete-plan delivery gate still requires actual plan pages in reviewer requests; notes cannot satisfy it.

## Repetition and recovery

Read signatures include requested/delivered range and source fingerprint. New ranges or changed source count as new evidence. The detector observes repeated unchanged action/results and short cycles; a repeated result alone is not a prohibition. Three repeated observations with repetition in the recent window first produce a targeted nudge; continued repetition triggers summary and context recovery; repetition after recovery pauses with an explicit blocker. Fresh evidence resets intervention state. These are initial experimentally chosen soft-intervention thresholds, not a new maximum job budget. Model-generated notes do not erase loop evidence simply by changing prose.

## OpenRouter stream and failure boundary

Only v2 coding jobs enable the host stream path. Existing ordinary Chief requests and older jobs retain their transport behavior. Chief assembles the full bounded SSE generation, reasoning and tool arguments, requires a completed terminal stream, then returns the ordinary journalled response. Partial/malformed/error/cancelled streams never return executable tool actions. Reasoning blocks retain their identity/order; the plaintext alias is not duplicated when structured details are present. SSE keepalives are not model progress.

The initial profile allows 120 seconds for first output, 90 seconds without output thereafter and 300 seconds total, bounded by the remaining attempt deadline. The Python HTTP timeout is 330 seconds. These initial conservative values require real latency measurement before further tuning; there is no claim they are optimal for every provider. Fixed failure categories distinguish timeout (first output/idle/total), transport disconnect, rate limiting, transient provider failure, cancellation and non-transient provider failure. Metadata includes elapsed time/call identity and generation identity when received. No free-text provider error is exposed.

After a recognized transient generation failure, the worker can make one fresh generation, counted against the existing allocation. No tool from the failed response was executed. Its old call remains uncertain if no complete journalled result exists; it is not replayed under a changed request key. A second consecutive failure pauses. Authentication, invalid payloads, checkpoint uncertainty and uncertain member dispatch do not enter that recovery path. Cancellation and deadline fences remain active. A lost non-streaming/provider response may still be billed; usage without a received accounting receipt remains unknown.

## Chief visibility and validation

Owner-scoped list/detail status exposes the current member, notebook, checkpoint time, last reported new evidence, worker counters, intervention counts and evidence count alongside the host-admitted shared model counter. Detail status includes bounded model stream samples and the last attempt-scoped failure. Samples are historical telemetry, not proof of current liveness or completion. Key notebook/recovery milestones use the existing Main delivery route, with a 60-second runtime cooldown; routine checkpoint/stream telemetry remains suppressed.

Synthetic tests exercise safe navigation, changed-source rereads, summary-before-deletion, protected reasoning/tool groups, failed checkpoint acknowledgements, loop escalation, fresh-generation recovery, resume and unread-plan approval refusal. Stream tests cover fragmented tools/reasoning, dual reasoning representations, terminal usage frames, CRLF boundaries, partial streams, provider errors and cancellation/stalls. These validate mechanisms, not model planning/coding quality. Paid inference and a successful real planning/coding trajectory remain separate acceptance work.

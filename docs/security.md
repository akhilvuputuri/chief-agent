# Security and data handling

## Trust and authorization

This is a personal, allowlisted deployment. Private Telegram chats establish identity before transcription or inference. Model output, listings, email, retrieved pages and user-sent files are untrusted. Telegram file paths are validated against the media directories we handle before download, downloads are size-bounded, PDF text is extracted in-process without font, script or rendering evaluation. Image bytes reach only the media specialist's model input during the turn they arrive; they are never persisted and are replaced by a placeholder in model-input traces. Zod schemas and owner-scoped SQL enforce tool boundaries; model arguments cannot choose an owner.

The Node process holds the integration credentials and calls tools directly. There is no internal HTTP tool callback and no shell tool in the gateway. Gmail is read-only. Calendar is read-only except for non-recurring events (timed or all-day) on the primary calendar, created after the owner taps the event's Telegram approval card; there are no guests, edits or deletions ([Calendar approval](calendar-approval.md)). IBKR access is read-only apart from order drafts. The host refuses any grant that would let Chief place, change or cancel an order; the owner reviews and submits drafts in IBKR ([IBKR](ibkr-portfolio.md#order-drafts)). Remote MCP tools are granted one by one in reviewed configuration, and writes must be idempotent ([MCP](mcp.md)). Gmail spends at most 40 API requests per turn, counting every list, metadata and body fetch but not the OAuth token refresh and mailbox-identity check; the ceiling is enforced in the adapter against the run identifier and returns a non-retryable validation error, so a search loop cannot walk the mailbox even if the model misbehaves. The scheduled briefing is charged under a synthetic run identifier unique to each firing, and a caller that supplies no run identifier shares one bounded bucket rather than being exempt. Retrieved email, like every other tool result, is persisted in `runtime_calls`; that table is not pruned today. Role deletion and skill activation require an exact owner approval; the model cannot approve its own proposal.

The gateway container drops capabilities, disallows privilege escalation, has a read-only filesystem and temporary storage, and does not mount the Docker socket. Gateway and Postgres ports bind to loopback. These controls are not a claim of production multi-tenant isolation.

## Isolated execution

- **Child agents** receive a brief, not the conversation. Their tools are the intersection of their definition, the registry grant and connected integrations. They cannot start other agents, and they keep their parent's foreground or background lane ([agents](agents.md)).
- **Coding** never runs shell commands in the gateway. Untrusted code runs in disposable EC2 boxes that hold no production secrets and have no instance profile. Model calls go through the host's authenticated proxy. The box holds no GitHub credential: the host publishes the reviewed artifact to a `chief/coding-*` branch with its repository-scoped App. Agent-side push through a separate App is implemented but dormant. The host merges only after the owner taps Merge on a card bound to the exact head, and that merge triggers the ordinary release. The card names any protected files the PR touches, such as credentials, permissions, execution controls, configuration, scripts or dependency manifests. Hard-stop paths (database, Compose, environment files and workflows) go to manual review and are never merged by the host, and the release still refuses database and Compose changes ([coding automation](coding-automation.md#pi-owner-confirmed-merge), [coding](coding.md), [boxes](boxes.md), [coding subagent](coding-subagent.md)).
- **Invoice browsing** runs in a separate browser container behind a public-only egress proxy. The owner logs in during a live handoff. The agent sees no password, input value, cookie or full page text, and has no arbitrary JavaScript tool ([gathering](gathering.md)).

Public page extraction uses hosted providers. URL checks reject local names, literal IPs and embedded credentials; provider network policy remains part of the trust boundary. No user cookies are forwarded.

## Persistence and privacy

Postgres stores conversations, voice transcripts, memories, domain records, model-response checkpoints and tool arguments/results. Execution records can contain personal data: treat the database, reset archives and backups as sensitive. Credentials are kept in private environment files and must never be injected into prompts or diagnostic logs. Credentials obtained at runtime are sealed with AES-256-GCM before they reach Postgres. IBKR tokens use `IBKR_TOKEN_KEY` with owner-bound associated data. Gathered invoice PDFs and saved browser state, which are not credentials, are also encrypted with owner-bound associated data ([gathering](gathering.md)). The first such credential was the Libby identity token for the NLB library assistant, which is sealed with AES-256-GCM under `LIBRARY_IDENTITY_KEY` before it is stored in Postgres, decrypted only inside the identity module, and never returned to the model or written to events, receipts, approval payloads or Telegram. This protects database dumps, backups, diagnostics and fixtures, not a compromised host that holds the key. `/reset` clears conversation history but not the library identity; `/library revoke` removes it and asks Libby to invalidate the copy.

Audio passes through Telegram and speech providers. Provider retention policies apply; do not promise end-to-end encryption or zero retention. `/reset` clears current conversation history, not every task, memory, trace or archive. Complete erasure requires an operator-reviewed data and provider retention procedure; a user export/erase flow remains future work.

## Recovery and limits

Persisted time/call budgets bound work; cancellation aborts model requests and prevents subsequent dispatch. Already-started external actions may complete. An interrupted write with an uncertain outcome pauses for inspection rather than replay. Read/model retries are bounded. These are not account-wide dollar spending limits.

Prompt injection can still affect prose or permitted low-risk mutations. Explicit memory intent is instructed to the model and is not independently proven. Source quote checks establish recorded support, not semantic truth. Keep existing approval boundaries and use provider spending limits. See [execution and recovery](reliable-execution.md).

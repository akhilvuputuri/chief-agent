# 160 — Can Chief call Anthropic directly, alongside OpenRouter, and switch between them?

Work date: 11 November 2026. Written: 11 November 2026.
Status: released in `a7c1993` (PR #441) on 11 November 2026, inert in production until enabled (the host has no key); tested with mocked requests and verified live with a temporary key on 11 November 2026 (local runs, not production; the OpenRouter fallback target and the sandbox were stand-ins). Enabling, owner-approved on 11 November 2026, is a separate Compose change through a reviewed operator procedure ([journal 161](161-enabling-direct-anthropic.md)).

## User-visible problem and preceding iteration

Every model call has gone through OpenRouter since the owned runtime ([journal 01](01-owned-runtime.md)). Since [journal 100](100-opus-main-model-and-caching.md) the main model and the `standard` agent tier are Anthropic's Opus 5.5, and the coding reviewer is too, so most model spend reaches Anthropic through an intermediary. The owner asked for a second pathway: the Anthropic Messages API directly, with a Claude Console key, with OpenRouter still supported and a way to switch between them.

What the earlier work established and this change keeps: Anthropic caches only marked requests ([journal 100](100-opus-main-model-and-caching.md), [104](104-opus-cache-misses-in-production.md)), and the reviewed price ceilings in `config/model-policy.json` stay in force ([deployment](../deployment.md#changing-the-production-model-through-a-release)).

## Diagnosis and alternatives

- **Per-model router (chosen):** every gateway model construction calls `ModelRouter.modelFor(slug)`. A slug goes direct only with `MODEL_PROVIDER=anthropic`, a key, a policy entry and listed prices within the ceilings; anything else is the unchanged OpenRouter adapter. The direct adapter returns OpenRouter-shaped generations, so the agent loop, journals, coding proxy and accounting need no provider branches.
- **A global switch for all models (rejected):** search, embeddings, the Jev pickers, the coding catalogue and other vendors' models exist only on OpenRouter.
- **OpenRouter's own Anthropic provider pinning (not chosen):** it keeps the intermediary, which the request was to remove.
- **Fallback to OpenRouter:** a new key, exhausted credits or a low rate-limit tier should not stop the assistant. Falling back only before any output keeps a call from being answered twice; cooldowns keep a dead key from costing one failed request per call. A 400 before any output is `rejected` and falls back that call only, so a rejected request shape (or a missing workspace header) cannot strand the assistant; the beta-enrollment 400 (`organization_not_enrolled_in_beta`) would fail every call, so it cools the direct pathway for 600 s. A 413 stays unclassified, because OpenRouter would forward the same oversized request to the same model.
- **Server-side refusal fallback (removed after review):** the first version opted in (`fallbacks: "default"`, beta `server-side-fallback-2026-07-01`). Independent review found it can serve a refused call on Opus 5 or Opus 4.8 at $5/$25, above the owner-approved $4/$20 ceilings, with sticky routing for later turns, and the adapter would have priced it at Opus 5.5's rates. It was removed: a refusal is now the existing non-transient `refusal` failure, with no fallback anywhere.
- **Thinking replay:** requests send `prefix_mismatch_behavior: "drop_block"`, so a replayed block whose prefix no longer matches is dropped instead of failing the call. The first version assumed drops came from history rebuilding in general and deferred an append-only shape. Live, every replayed in-turn block was dropped (73 of 73), and the cause was narrower: Chief ends each request with a per-call state message (`src/context.ts`) and rebuilds it every call (`src/custom-agent.ts`), so the state message that preceded a block had gone by the next call. An earlier live probe that kept each earlier state message in place, as a mid-conversation system message between the tool results and the next assistant turn, was accepted by the API with no drops at similar cost.
  - **Chosen: rebuild the prefix inside the adapter.** The adapter remembers, per returned thinking block (keyed by a hash of its signature or data), the exact state text its request ended with, in a bounded in-process memory (2,000 entries, 8 million characters, least recently used first, nothing logged). When translating a later request, it puts that state back before the assistant turn that replays the block, exactly as sent. Nothing else in the prefix changes within a turn: the top-level system blocks are constant within a turn, cache marks do not count, and Chief's tool list is constant except on a child's final call. The placement is valid because the state follows the tool results (or the owner's message) and precedes an assistant turn. A replay retried without thinking re-inserts nothing; after a restart the memory is empty and blocks are dropped as before.
  - **Scoped to the owner and run (review follow-up).** The first version keyed the memory by the block's signature alone, process-wide, so a request carrying another context's block (the coding worker API accepts arbitrary `reasoning_details` from sandboxes) would have had that context's private state text inserted. The key now also hashes the call's spending scope (owner and run), the one host-set scope present at `generate()` for every owner, agent, research and learner run and shared by a run's consecutive calls, without changing the adapter interface. `cacheKey` was not chosen: it is per owner, not per run, for the main model, absent for agents, and a coding call's is host-built but its messages come from the sandbox. Calls without a spending scope (coding) record and insert nothing; their requests carry no trailing state from Chief. Nothing is lost across turns, since each owner message is a new run and older turns' reasoning is projected out of history.
  - **Rejected: storing the state text in the stored reasoning entry.** It would survive restarts, but it copies private runtime state (time, work, conversation and thread context) into every stored reasoning entry in authoritative history, enlarging payloads, for a cache and continuity gain that matters mostly within one turn.
  - **Rejected: changing Chief's context assembly** to keep state messages in place for every model: it changes OpenRouter requests and Chief's runtime context, outside this change's scope.
- **Truncated tool calls:** OpenRouter returns a truncated tool call's raw argument text, which fails `JSON.parse` in the agent loop and is reported to the model, so it never runs. The direct adapter now accumulates each tool call's streamed `input_json_delta` text and, when a response stops at `max_tokens` inside its last tool call, returns that raw text for it (made unparsable if it happens to parse). This is the closest equivalent; emitting arbitrary invalid arguments would lose what the model wrote.
- **Interleaved thinking (review follow-up):** replay used to put every thinking block before every visible block, but Opus 5.5 can return a thinking block before each tool call. Each stored entry now records `position`, the index of the visible block it preceded in Chief's stored shape (`[text when non-empty, tool_calls…]`, text counting as preceding it when any text came before it), and replay rebuilds that order; older entries without it lead, as before. A response with text after a tool call still cannot be rebuilt exactly, because Chief stores one joined text. Not observed live (above), so tested with mocks only.
- **Remembered rejections (review follow-up):** a block the API always rejects used to cost a 400 and a replay-free retry on every call. After a successful retry, the blocks replayed in the rejected request are remembered (per scope, by signature hash, at most 1,000) and skipped afterwards; later requests then match the retry's prefix, so the retry's own blocks keep their state.
- **Prompt too long (review follow-up):** such a 400 falls back to OpenRouter, where it fails again. The API gives it no structural discriminator (no `error_code`, no SDK error class; measured above), and the adapter never matches message text, so the behaviour stays and is documented as a limitation.
- **Foreign tool-call ids:** mapped deterministically on the wire (sanitized prefix and a 16-character hash, at most 57 characters; the API documents the pattern but no maximum length here, so they stay well under 64), identically for `tool_use` and `tool_result`, so the prefix stays stable for caching and thinking replay. Stored history and returned ids are unchanged. A per-turn id recurring in later assistant turns stays identical; the API accepts that (measured above), so ids are not made unique per request.
- **Refusals in coding jobs:** a new failure code (`model_refused`) would cross the worker boundary: the Python squad's known-code list (`coding_runtime/src/chief_coding_runtime/model.py`) and the Pi runtime would need changing, and those are sandbox runtime paths. Instead the existing `model_provider_failed` code stays, and the stored failure gains `providerFailure: "refusal"` and the `refusalCategory`, so a paused job's status says the model declined, and why. No migration.

## Implementation and review

- [`src/anthropic.ts`](../../src/anthropic.ts): `AnthropicDirect` on the official SDK, streamed, SDK retries, logging and telemetry off. Thinking blocks are stored in `reasoning_details` under the `anthropic.thinking` tag and replayed only on the direct route. Server-side refusal fallbacks are deliberately never requested. Faults before output are classified as `auth`, `permission`, `billing`, `rate_limit`, `unavailable`, `not_found` or `rejected`; every direct failure's diagnostics carry `route: "anthropic-direct"`, plus the API's `errorType` and `errorCode` enum values when present. Three explicit cache marks (the opening stable system block, as `cacheHints` does on OpenRouter, the owner's current message and the last block before the per-call state message) and no top-level automatic mark. A pre-output 400 on a request that replayed thinking retries once without it (`replay_dropped`). Every received chunk, pings included, reports streaming progress, so a long thinking phase does not trip the coding idle timer. An optional `workspaceId` is sent as `anthropic-workspace-id`.
- [`src/model-router.ts`](../../src/model-router.ts): routing, the one-call OpenRouter fallback and per-process cooldowns (600 s for key, permission, billing, unknown-model and beta-enrollment faults, the `retry-after` hint within 5–120 s for rate limits, none for outages or other rejected requests). Key, billing, rate-limit and beta-enrollment faults cool every model; permission and unknown-model faults only the failing one. Every OpenRouter adapter strips direct-route reasoning, whatever the model's vendor, and passes requests without it unchanged.
- `config/model-policy.json` gains `providers.anthropic` (fallback on, Opus 5.5 mapped); `config/runtime.json` and the code default set `MODEL_PROVIDER` to `anthropic`, which is inert without a key. `src/main.ts` routes the main, media, agent, learner, judge and coding-factory models through the router and logs `model.routes` at startup. `model.completed`/`model.failed` gain `route` and `fallbackFrom`, `model.provider_fallback` is new (with `reason`, `cooldownS`, `httpStatus`, `errorType`, `errorCode`), the saved CloudWatch queries show those fields, spans name `anthropic` as the provider on the direct route, and direct charges are labelled `anthropic-main`.
- Follow-up from the live runs: the raw truncated tool input, tool-call id mapping and the per-block state memory described above in `src/anthropic.ts`; failures after a complete, billed response carry normalized `usage` in their diagnostics, which `model.failed` log lines (`src/ops-log.ts`) and failed spans (`src/otel.ts`) now report as tokens and cost; the coding controller records such a failure's usage as a `model_usage` event marked `incomplete: true`, and stores `providerFailure: "refusal"` with its `refusalCategory` for a refusal. An aborted direct call still logs no route: the adapter rethrows the caller's `signal.reason` unchanged, and the logging site cannot tell the pathway without changing that contract.
- `ANTHROPIC_WORKSPACE_ID` (optional, `wrkspc_…`, default empty) is a private environment identifier beside the key, not a `config/runtime.json` setting, because that file refuses identifiers.
- The Compose lines that would pass `ANTHROPIC_API_KEY` and `ANTHROPIC_WORKSPACE_ID` to the gateway are deliberately not part of this change, because the release guard refuses Compose changes. `scripts/deploy-anthropic-key.py` permits exactly those two lines, in that order, after the gateway's `OPENROUTER_API_KEY`.

Operator guide: [model providers](../model-providers.md). Independent review: the first review requested changes (the refusal-fallback price exposure above, 400s stranding the assistant, the cache mark on the per-turn summary instead of the stable system message, stripping only for `anthropic/*` slugs); they were addressed. A later review approved head `162bf66` with non-blocking findings: the process-wide state memory, thinking order on replay, recurring tool ids, retried permanent rejections, the prompt-too-long fallback and three stale comments (`src/model-router.ts` on repeated progress, `src/coding/controller.ts` on the idle timeout, and an unexplained `.catch` on the incomplete `model_usage` insert). They are addressed in the working tree (above; the comments corrected, no controller behaviour changed) and await re-review.

## Verification and outcome

Implemented, tested with mocks and verified live on 11 November with a temporary key (above). The fixes from the live runs were measured before and after:

- **Truncated tool call** (120-token allowance): the previous head returned `{"key":"poem"}`, which parses; the fix returns `{"key": "poem"`, which does not.
- **Foreign ids:** HTTP 400 on the previous head; HTTP 200 with the mapped ids, the same in `tool_use` and `tool_result`.
- **Thinking continuity, Chief-shaped loop** (two leading system messages, a state message rebuilt every call, parallel tool calls, 6 calls at high effort; local scripts, not in the repository): previous head 10 of 10 and 8 of 8 replayed blocks dropped; with the fix 0 of 9, 0 of 9 and 0 of 2. Cache reads about 97% of prompt tokens in both; $0.060–0.068 per loop with the fix against $0.077–0.134.
- **Thinking continuity, Chief's real runtime** (the `tools` scenario: parallel email and parcels agents, a calendar approval, a stocks agent): previous head 16 of 16 replayed blocks dropped on its 22 direct calls; with the fix 0 of 6 (cold cache) and 0 of 7 (warm), 85.8% of prompt tokens read from cache against 84.7%, $0.38 against $0.45 for the direct calls. The cold run's agents read nothing on their first calls because the 5-minute cache had expired before it; its later calls read 85.5%.

No latency, cache hit rate or cost comparison with OpenRouter exists, because no OpenRouter key was available. The first production run must verify authentication (and the workspace header for an unscoped key), the effective model, cached tokens, `thinking_dropped`, acceptance of the thinking-binding beta, a Pi coding job with a direct reviewer, rate-limit behaviour on a new low-tier account and fallback firing ([checklist](../model-providers.md#first-live-run)).

## Coding-harness learning record

Updated in [coding-agent lessons](coding-agent-lessons.md). Direct calls report streaming progress on every received chunk, pings included, so the coding controller's 90-second idle timer does not abort a reviewer that is only thinking. The host proxy boundary is unchanged: sandboxes still hold no provider key and call the host, whose model factory now goes through the router. Once enabled, the coding reviewer (`anthropic/claude-opus-5.5`) would run direct; the DeepSeek coders stay on OpenRouter. Pi's OpenAI-completions client keeps only OpenAI-style reasoning entries, so it drops the direct route's thinking entries between tool turns; with `drop_block` that costs continuity, not failed requests. Measured live on head `da1eb07` with the job's roles on Opus 5.5 direct: plan, code and review jobs reached `pr_ready` with an APPROVE at about $0.25 each, a flawed candidate was rejected, and a 690-second thinking call survived on ping progress. A refused coding call now keeps `model_provider_failed` but stores `providerFailure: "refusal"` and its category, and any failure after a billed response records a `model_usage` event marked `incomplete`.

# Chief engineering journal

The journal connects the assistant's implementation, production incidents, experiments and releases. Read it as an evolving engineering record: a fix can pass its intended checks and expose a different failure in the next iteration. The timeline is ordered by work dates; entry numbers and filenames remain stable when earlier work is documented later. Dates follow the original work records, with later verification dated separately. Entries first reconstructed on 9 September 2026 use repository history and incident reports; this index was updated on 23 September 2026 to link the context follow-up and current-status guide.

For the latest verified release and open work, read [current work](../current-work.md); this index is a dated history, not a live-status dashboard. Earlier rollouts and their exact evidence remain in the linked entries. A released implementation does not by itself establish improved answer quality, lower cost or completion of its live acceptance checks.

**Context, cost and continuity.** The [lost-target incident](02-context-and-targets.md) and [cost investigation](03-token-cost.md) led to more selective context, compact observations and search reuse. As attachments and tool definitions grew, the [PDF failure and context-budget follow-up](07-attachments.md) exposed pressure from fixed instructions, schemas and state; the exact production size was not captured, so that diagnosis remains qualified. The v0.3.4 fix kept the current input and newest tool group viable, but the later [rolling-conversation incident](17-rolling-conversation.md) showed that bounds alone could still omit the immediately preceding exchange. That iteration protected recent conversation and source links, improved original-message retrieval, and separated foreground chat from explicitly selected jobs. [Checkpoint steering](18-checkpoint-steering.md) then changed when new input is adopted, preserving completed reasoning/tool results while fencing stale delivery. These are connected, evidence-backed iterations; the record does not establish one sole cause for every conversational failure or a measured cost reduction from the whole sequence.

**Delegation and instructions.** [Versioned skills](20-versioned-skills.md) made instruction identity explicit. The [research specialist](08-research-specialist.md) separated source-heavy child context; [independent review](10-foundation-review.md) exposed cache and accounting gaps before the dependent [alignment capability](09-job-alignment.md) shipped. [Media delegation](12-media-specialist.md) reused that boundary. [Portable plugins](15-portable-plugins.md) subsequently made compatible definitions movable and pinned them to tasks, with a review correction for long instruction paging. [Boxed sub-agents](91-boxed-subagents.md) take the next step: heavy work in on-demand EC2 boxes that Chief can steer and close, now running in production, with coding attempts moved onto them.

**Storage and memory.** [Normalized storage](16-authoritative-storage.md) addressed repeated persistence and bounded retrieval, with before/after storage measurements. It also made original conversation sources available for the [continuity work](17-rolling-conversation.md). [Observable memory](06-observable-memory.md) is a separate unfinished design for sourced, selected and versioned memories; durable history and a successful storage release do not complete it.

**Delivery and operations.** The [foundation and voice account](19-foundation-and-voice.md) records the initial integration boundary. [Telegram views](11-telegram-views.md), [HTTPS](13-miniapp-https.md) and [persistent canvases](14-persistent-canvases.md) follow the progression from messages to browsable documents. [Cloud development](05-cloud-development.md) and the [specialist review correction](10-foundation-review.md) explain how inspection and release discipline evolved alongside the product. Architecture and operator instructions stay in their linked guides.

## Keep the record useful

Follow the a-stack `journal` skill and its evidence rules: label claims as reported, tested, measured, hypothesis or deferred; release closures need exact deployed-SHA evidence. In this repository:

- Use [the template](TEMPLATE.md).
- Update this timeline and the relevant topic path without renumbering older files.
- Link architecture guides and runbooks rather than copying their procedures.
- A supplied memory or context item is not proof that the model used it. A health check is not a semantic evaluation. Do not claim benchmark wins, production scale or savings without measurements.
- Keep private conversations, credentials, raw traces, user records and personal motivations out of the journal.

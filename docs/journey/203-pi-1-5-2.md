# 203 — What does moving the coding runtime from Pi 1.1.0 to 1.5.2 change, and which advisories does it close?

Work dates: 2026-11-16 and 2026-11-17. Written: 2026-11-17.
Status: tested, not yet released. The coding runtime pins `@earendil-works/pi-coding-agent` and `@earendil-works/pi-ai` 1.5.2. One thing of ours had to change: the worker's `grep` now roots its `glob` at its `path`, as Pi's description of the tool says since 1.5.1. OSV flags nothing in the Pi runtime's lockfile any more. Six undici advisories that OSV records by Git range only still apply to the pinned undici 8.12.3; no published Pi pins 8.12.4. No coding job has run on 1.5.2.

## User-visible problem and preceding iteration

No incident. [Journal 162](162-advisories-in-the-dependency-tree.md) (11 November) left two findings that only a Pi upgrade could close: `pi-coding-agent` 1.1.0 pins undici 8.10.2 and minimatch 10.2.6 exactly, both versions have published advisories, and Kite does not support `overrides`. The owner asked for the upgrade on 16 November.

Between that entry and this one the runtime was rebuilt to run Pi as shipped (journals [182](182-pi-tools-and-prompt-as-shipped.md), [190](190-pi-native-anthropic-protocol.md) to [193](193-rebase-backstop-limits.md)), and its own undici dependency went away with the client it served (journal 190, PR 479). The copy Pi pins is now the only undici 8 a worker loads.

## Diagnosis and alternatives

- **The one break was a copy.** The worker carries its own `grep` because stock `grep` searches hidden files and offers no way to leave `.git` and `.env` out. It takes Pi's schema and description and replaces only the function that runs ripgrep. When Pi changed what `glob` means and said so in the description, the model was told one thing and the worker did another: with `path: "repo"`, `glob: "migrations/main/*.js"` found nothing. Stock 1.5.2 fixes this by running ripgrep inside `path` and searching `.`; the worker now does the same, and drops a leading `./` from the glob as stock does.
- **Other differences from stock `grep` were left.** Stock also floors `context` and `limit`, keeps a lone carriage return inside a line, and holds the limit notice until another match proves there is one. None of these is something the description promises, and the worker already took context from ripgrep and never read ripgrep's configuration file. They are listed here so the copy's drift is known.
- **`typebox` did not move.** `pi-ai` no longer depends on it, but `pi-coding-agent` 1.5.2 still does, at the same 1.3.27, and builds its own tools with it. The runtime imports it directly for one tool.
- **undici 8.12.3 is not the newest.** undici 8.12.4 fixes six advisories against 8.12.2 and 8.12.3 (GHSA-mqg3-3v4r-cm32, high; GHSA-7xg3-fphp-28hg, GHSA-5rm8-gv32-r954, GHSA-9v6h-8rgp-m69f, GHSA-3g9m-rv3r-w5w2 and GHSA-r4pc-4jcp-7pqc, medium). OSV holds the high one as CVE-2026-116592 with a Git range and no npm range, so the query above does not return it for 8.12.3. Kite does not support `overrides`, by design, so the copy Pi pins cannot be raised from here, and it was not worked around.
- **What those six concern, read in undici's release notes and Pi's source, not tested by attack.** Five are in undici's cache, redirect, decompress and dump interceptors. The worker's default dispatcher is a plain `Agent` with none of them: Pi composes no interceptors, and sets up its own dispatcher only in its command-line entry points. The sixth is the integrity check in undici's own `fetch`, which the worker does not use (its `fetch` is Node's, and nothing passes `integrity`).

## Implementation and review

- `coding_runtime_pi/package.json`: `@earendil-works/pi-ai` and `@earendil-works/pi-coding-agent` 1.1.0 → 1.5.2, changed with `kite install … -E`. `typebox` and the development dependencies are unchanged.
- `coding_runtime_pi/package-lock.json` and `package-lock.json` (the worker image installs from the second): Pi's seven packages at 1.5.2; `@earendil-works/pi-schema` 1.5.2 added; undici 8.10.2 → 8.12.3 where Pi resolves it; minimatch 10.2.6 → 11.0.3 with its new dependency `@isaacs/nonrecursive-glob-match` 1.1.0; `grok-mermaid` replaced by `lovely-mermaid` 0.3.3; `marked-cjk-friendly` 0.1.2 added; `@earendil-works/chord` removed, and with it esbuild 0.28.2 from the runtime's lockfile (tsx keeps its own). Checked by script against the previous lockfiles: nothing else changed.
- `coding_runtime_pi/src/tools.ts`: `grep` runs ripgrep inside a directory `path` and searches `.`; a leading `./` is dropped from `glob`. A file `path` is searched as before. The exclusions for `.git` and `.env` files are unchanged and still come after the model's glob.
- `coding_runtime_pi/tests/runtime.test.ts`: a test of the new contract, which fails on the old function with "No matches found".
- Comments that cited Pi 1.1.0 as their source were re-read against 1.5.2 and updated: the cache-warming label in `coding_runtime_pi/src/model.ts`, and the allowlist notes in `src/coding/pi-messages.ts` (the top-level effort is `low` now; why `thread` is never sent; where a failed tool's images go). No behaviour of the host changes.
- No database, Compose or configuration change. The worker image pin is a separate change after this one is released.

## Verification and outcome

- **Tested, a Mac on Node 22.23.4:** after a clean `kite ci` from both lockfiles, the repository's `kite run check` exited 0 in 3 min 26 s: 1,840 TypeScript tests with one skipped, the script and Python tests, and the Pi runtime's own check (55 tests, one of them new). `kite run format:check` passed.
- **Tested through the host:** `tests/coding-pi-messages.test.ts` and `tests/coding-one-session.test.ts` (55 tests) run real Pi sessions through the host's allowlists, including Pi's own compaction call and its retries; all pass on 1.5.2.
- **Not verified:**
  - No coding job has run on 1.5.2, and no request built by 1.5.2 has reached Anthropic. The wire comparison used a stand-in server.
  - The Linux process guard and the container smoke run only in CI.
  - Idle cache warming was read, not exercised: a refresh needs about four and a half minutes between a run's last model call and the session's disposal, and an expected saving of at least $0.05.
  - The shorter system prompt and the new validation messages change what the model reads; their effect on a job is not measured.
  - The release notes were read for what the runtime uses. Pi's terminal interface, other providers, MCP and code mode were skimmed.

## Follow-up and next iteration

- Release this change, build a worker image from it and pin it by the procedure in [boxes](../boxes.md#phase-6-codebuild-removed) ("Re-pinning the Pi worker image"). Then read the first job's record for refused requests (`messages_field_refused`, `beta_refused`) and for `cache_warm` calls.
- Upgrade Pi again when a release pins undici 8.12.4 or later; that closes the six advisories above.
- hono 4.13.13 and `@hono/node-server` 2.1.3 are flagged since 12 November. Whether Chief reaches them (they arrive with the MCP SDK's server modules, which journal 162 found Chief does not import) has not been checked for these advisories.
- The worker's `grep` is a copy of part of stock `grep` and will drift again. A way to pass exclusions to stock `grep` would remove the copy; none exists in 1.5.2.

## Diagnosis and intervention

The baseline failures were workflow completion contracts, not native transport rejection. The tool schema advertised report kinds invalid for its current intent and a larger planning-summary limit than the executor accepted. The candidate advertises only the current intent's kinds and actual bounds. A clean prose-only ending may receive one report-only prompt; source/command tools are deactivated, the original allocation applies, and no report can supply owner approval or check receipts. A question, review changes or repeated failure still stops honestly. A later Gemini reviewer treated the approved plan’s starting-state description as a false claim about the completed source; the bridge now labels historical intent versus current candidate, without forcing an APPROVE verdict. The runtime also incorrectly displayed “No implementation approved” in the separate reviewer’s system context; review-only permissions now remain distinct from the candidate’s host-validated owner approval. The bridge supplies pinned base and changed-path manifest without granting source writes or access to another workspace. Pi provider empty/length responses receive fixed transient/incomplete diagnostics while uncertain journal entries remain non-replayable; no automatic provider retry or allocation change is added.

Synthetic counterexamples verify one finalization, no automatic repeated prompt, no call after exhausted models/tools, and refusal of a write during build finalization with actual failed checks remaining failed. Native fixtures cover the eight exact catalog profiles plus a generic profile, replaying structured and opaque signatures through tool continuation. The role-command regression snapshots all eight models without changing existing settings or another owner.
